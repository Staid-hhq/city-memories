# T15 隔离原图规模验证

仅用于本机 Windows / Microsoft Edge，**不会连接私人数据目录或使用现有账号**。需要项目现有 Python 虚拟环境、前端锁定依赖、空闲的 8000/5173 端口以及至少 40 GiB 可用磁盘空间。没有预置正式账号，不需要地图 Key。不安装全局依赖，也不会接管用户的浏览器配置。

在项目根目录生成不同内容的合成原图：

```powershell
backend\.venv\Scripts\python.exe validation/scale/generate.py
```

生成 3400 张带有明确合成标记的 JPEG/PNG/静态 WebP：340 张 4000×3000、2720 张 2560×1920、340 张 2048×1536。随机种子固定，每张纹理不同；清单包含大小、尺寸及 SHA-256，禁止用少量重复文件冒充规模。已存在的完整清单逐份复核后复用；不覆盖未知的半成品目录。可用 `--count 10` 单独生成试样，但试样不用于正式规模验收。

然后在 `frontend` 目录执行：

```powershell
npm run test:scale
```

这是显式启用的重量级测试，不包含在日常 `test:e2e` 中，超时上限 30 分钟。每次新建隔离数据库与独立 Edge 配置；服务端不复用现有端口。独立 HTTP 驱动还会核对测试目录标记及当前服务身份，防止直接运行脚本时误用其他本地服务。

## 测试内容

1. 在真实 Edge 页面注册合成账号、建影集，核对并上传/提交 400 张原图，要求 400 个上传响应全部成功，不自动重试掩盖失败。
2. 经正式 HTTP 导入协议，两账号并发上传：主账号补足 3000 张（8 本影集），另一账号 400 张。每批不超过 400，每账号一路上传；保留正式全局两路接收、限流、校验和维护逻辑。
3. 页面加载完整 400 张元数据，对比数量、稳定 ID、文件名及顺序；远离视野的原图卸载。
4. 双账号各 30 轮列表、统计、文字、400 张排序与部分原图读取；核对越权 404、真实同版本竞争 200/409，最后恢复原顺序。
5. 20 轮预热 + 20 轮不刷新的 SPA 进出与原图切换；固定同一滚动位置，等待全部近视口图片 `naturalWidth > 0`，记录 Windows 测试进程内存、JS 堆、DOM、Blob URL 和长任务，退出必须释放全部 Blob URL。另测 CDP 模拟 20 Mbps / 80 ms 下的 12MP 原图，不称为实际公网测速。尺寸就绪不等于精确解码/绘制耗时，结果中 `originalDecodeMs` / `throttled12MpDecodeMs` 沿用字段名但仅代表此观测时间。
6. 主账号 3000 张经正式 API 移入回收站，完整核对分页、归属和统计，再按原影集顺序逐份恢复。第二账号保持 400 张，不受影响。
7. 校验 SQLite 完整性、外键、归属、文字与顺序，并逐份比对 3400 份源文件和系统副本 SHA-256。服务停止后持有正式维护锁，测 30 轮完整清理逻辑；不制造到期条目，不删除有效照片，再次核对全部文件。

本机工程门槛：首批照片元数据、文字保存及排序 HTTP p95 ≤ 1000 ms；3000 条回收站首批同样检查。内存防回归门槛：本轮 CDP 返回的 Edge 测试进程私有字节采样总和 < 4 GiB，后端 < 1 GiB；相同页面状态的第 36–40 轮与第 21–25 轮中位数相比，Edge 增量 < 256 MiB、JS 堆增量 < 32 MiB、DOM 增量 < 1000。前 20 轮作为浏览器原生图片缓存/分配器预热，其采样仍计入峰值。阈值不是产品上限或长期无泄漏承诺。

## 结果、安全与磁盘

结果均位于 Git 忽略的 `validation/scale/results/`：

- `fixtures-3400/manifest.json` 及合成图片：约 7.89 GiB。
- `t15-runtime-*/`：每轮独立测试账号、数据库、随机认证密钥及保存副本，完整轮约再占 7.89 GiB。故意保留，供服务停止后的维护与字节核查使用。
- `population.json`、`benchmark.json`、`lifecycle.json`、`maintenance.json`、`audit.json`、`browser-metrics.json`：本轮原始记录；后一次运行会覆盖同名记录。
- `browser/`：Playwright 状态、合成内容截图及失败线索。原始日志、凭据、数据库和截图都不应加入公开提交。公开交付仅放匿名汇总。

2 秒一次内存采样可能漏掉瞬时峰值；Windows 工作集总和会重复计算共享页，因此使用私有字节作为主要指标。每轮对比点等图片加载完成，并主动执行 JS GC 以观察残留；全程周期采样不强制 GC，同时记录峰值与资源释放。没有缩略图，也没有改写原图。

`CITY_MEMORIES_SCALE_RESUME=1` 仅用于排查后半段：复用最近一次 `server.json` 指向、通过目录边界和专用标记检查的合成库，要求主账号已有 3000 张，再运行双账号基准、浏览、回收站与审计。它会跳过已完成的生成/导入/400 张页面全分页，输出明确标记 `diagnosticResume: true`，**不能代替默认从零执行的完整交付验收**。排查后清除该进程环境变量，再执行默认命令。缺少标记、数量不符或服务占用端口时直接失败，不回退到私人库。

可复核小型安全测试与静态检查：

```powershell
backend\.venv\Scripts\python.exe -m pytest validation/scale/test_harness.py -q
backend\.venv\Scripts\ruff.exe check --config backend/pyproject.toml validation/scale
```

清理测试产物前先停止测试服务，逐个核对 `server.json` 中绝对路径、`t15-runtime-` 前缀与 `t15-isolated.txt` 的 `synthetic-only` 标记；路径必须直接位于本项目 `validation/scale/results/` 下。只删除明确核对过的测试目录，不使用模糊通配删除，不触碰 `.local-data/` 或源照片。需要保留失败证据时先另存对应的结果文件。

实测结论、硬件、失败轮次与局限见 [T15 交付报告](../../docs/t15-scale-verification.md)。
