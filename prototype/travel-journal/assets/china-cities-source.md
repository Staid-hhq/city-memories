# 中国城市目录与按需边界来源

本原型使用天地图官方行政区划 V2，说明页面：
http://lbs.tianditu.gov.cn/server/administrative2.html

请求由真实浏览器发往天地图官方 HTTPS 接口，使用本项目既有浏览器端应用 Key。密钥仅从本机 `map-config` 在运行时读取，不保存在本文件或脚本中。国家目录与城市边界只做当前页面内存缓存，不生成可再分发的完整行政边界数据包，也不抓取地图瓦片。

## 本次已验证

- 在浏览器中查询 `中华人民共和国`、`childLevel=2`、`extensions=true`，HTTP 200、业务状态 200；响应 59,352 字节，527 个行政节点：国家 1、省级 34、市级 368、区县级 124。
- 同次响应国家的 `boundary` 为空字符串；子级城市仅含编码、名称、中心点和层级等资料。这次响应没有提供全国或全体地级边界。
- 在浏览器中单独查询深圳、`childLevel=0`、`extensions=true`，HTTP 200、业务状态 200；响应 4,039 字节，边界为 3,844 字符的 `MULTIPOLYGON` WKT，中心点为 `[114.052857, 22.545676]`。
- Node 服务端使用浏览器端 Key 会被拒绝，官方返回 403 / 301012，提示浏览器端 Key 应在浏览器使用。因此本模块不做服务端代理，不伪造浏览器身份。

上述节点数是官方接口当次目录层级统计，不应直接解释为 368 个内地地级市。返回名称与层级须与上级关系一起使用。

## 数据约定

`china-map-data.js` 暴露 `window.ChinaMapData.load()`、`boundary(city)` 与显式调用的 `outline()`。目录转换为 GeoJSON `FeatureCollection`；每个城市入口至少包含：

```js
{
  type: 'Feature',
  properties: {
    id: '156440300',
    adcode: '156440300',
    name: '深圳市',
    center: [114.052857, 22.545676],
    level: 3,
    parentName: '广东省',
    kind: 'prefecture'
  },
  geometry: null // 目录没有边界时保留 null，按需请求后得到 Polygon/MultiPolygon。
}
```

- 以省级节点下的市级行政单位为主要城市入口，包括接口列出的自治州、地区、盟等地级单位。
- 不能仅凭接口 `level=3` 认定地级行政城市。实际目录还混有中农发山丹马场、莲花山风景林自然保护区、太子山天然林保护区等非城市节点；内地市级节点仅保留名称以“市 / 自治州 / 地区 / 盟”结尾的单位，台湾节点保留县、市。被排除的节点记入 `metadata.excludedNonCityUnits`，不生成城市入口。
- 北京、天津、上海、重庆按完整直辖市作为入口；香港、澳门各有独立入口，不展开为其区级目录。
- 省级节点下直接返回的县级单位保留为 `direct-admin-unit`，不伪称地级市；界面可结合上级地区标明。
- 台湾省下返回的市、县入口按官方当次层级保留；如果任何省级节点缺少子目录，不把整省伪装成地级城市，限制写入 `metadata.notices`。
- WKT 转换保留所有多边形、岛屿和内环，不抽稀、不另绘国界。使用原始经纬度；对空值、无效 WKT 或非经纬度 SRID 返回 `null`。
- 界面只在城市已有照片时调用 `boundary(city)`；相同查询和边界请求在当前页面复用。目录、背景和城市请求共用严格串行队列，开始间隔至少 1500 ms；没有全城市逐一查询或后台预取。

`load()` 返回的 `outline` 字段仅在官方国家节点确实提供可解析边界时才包含 GeoJSON Feature；当前实测为 `null`。

为满足本机原型“中国背景”的实际显示需求，调用方明确调用一次独立的 `outline()`：依据本次全国目录中的 34 个省级节点，按上述串行节奏分别查询边界，仅在本页面内存缓存。它返回背景用的 `FeatureCollection`，由界面以同色填充、细省界、背景不可点击的方式呈现；城市选择和有照片点亮仍由独立城市层负责，没有省级钻取流程。

`outline({ retryMissing, onProgress })` 提供 `{ processed, total, loaded, missing, pending, collection }` 进度，其中 `missing` 为数量，详细原因在 `collection.metadata.missing` 中。回调错误不终止请求；几何范围在取得单份数据时计算，后续快照不反复遍历全部顶点。302010 会记录为请求频率受限，界面提供手动重试，不自动反复请求。

这不是国家接口返回的单一国家轮廓，也不是地级市完整边界数据集。返回的 `metadata` 记录请求数、成功数、缺失地区与原因、全部几何经纬度范围、顶点数和是否取得 34 份边界。部分失败保留明确缺失记录，不自动反复请求；仅用户明确重试时，调用 `outline({ retryMissing: true })` 重新查询失败节点，并复用已经成功的几何。全部面、岛屿和最南几何都会保留给渲染层；是否另含海域线取决于接口真实返回，不能由 34 份成功推断已具备完整国家版图要素。

2026-09-21 的真实浏览器验证取得 34/34 份背景，缺失为 0，74,118 个顶点，范围为 `[73.498962, 3.832541, 135.087387, 53.558498]`。页面显示 380 个城市及同级/特殊单位入口，已测试深圳与成都区域点亮；本次未再出现 302010。完整背景首次加载约一分钟，刷新后重新请求。详见 [新版关键检查](../../../docs/page-flow.md#新版地图关键检查2026-09-21)。该结果不等于所有国家版图要素或全国城市映射已验收。

## 使用范围

来源应注明天地图。参阅 [服务条款](https://www.tianditu.gov.cn/about/service)、[版权声明](https://www.tianditu.gov.cn/about/copyright) 与 [配额说明](https://cloudcenter.tianditu.gov.cn/center/development/quotaDesc)。接口正常返回不等于获得批量爬取、永久打包或再分发地图数据的授权；本轮仅作本机原型的正常在线查询与页内缓存。
