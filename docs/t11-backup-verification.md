# T11 · 一致备份与恢复工具交付记录

日期：2026-10-03。状态：已完成。依据 [开发计划 T11](development-plan.md)、[技术方案](tech-stack.md) 和 [数据设计](data-api-design.md)。开发无需用户提前准备硬盘、密钥或外部服务；所有验证使用临时目录、测试账号和合成图片，**未为用户真实资料创建备份，也未恢复或覆盖真实数据库/照片**。

## 交付结果

新增 `python -m city_memories.backup` 三个离线命令：`create` 创建并完整校验备份，`verify` 再次检查全部备份，`restore` 仅恢复到全新目录。没有网页入口、远程上传、系统计划任务、强制覆盖或自动删除旧备份。

维护窗口采用正常停止后端（含重载父进程）后执行命令，工具与应用、清理及在线 Alembic 迁移共享操作系统锁，未停服务会拒绝开始。使用 SQLite Backup API 读取完整已提交数据，包括 WAL；不是简单复制单个正在使用的数据库文件。

保留快照时的账号、城市、空影集、有效照片、未到期回收站、文字、顺序、归属和已提交收据；原图逐份复制并校验大小/SHA256，同内容的副本分别保留。不复制认证密钥、运行配置或上传暂存；在快照副本清除旧会话、限流记录和已到期/purging 照片，关闭未提交导入，源资料不变。

清单记录格式/迁移版本、快照时间、各表数量、数据库大小/哈希，以及逐份照片元数据摘要、大小和哈希。校验数据库完整性、外键、关系和目录成员。恢复开始与结束重新核对期限，满 30 天不重新计时；旧 Cookie 无效，原用户名密码仍可登录；已剔除照片不会因为重放原收据而重新生成。

只写 Git 工作区外、父目录存在且最终目录不存在的目标，禁止互相包含、覆盖和合并，拒绝网络/链接路径。失败或中断留下未完成标记，应用/迁移拒绝启动；完整备份也不能直接当成数据目录使用。工具不递归删除失败目录，原资料和好备份保留。

操作与排障见 [备份恢复说明](backup-restore.md)。支持备份格式 v1、迁移 `b61e24f803a7`，API 版本 0.11.0；无新依赖、表或迁移。

T11 专项覆盖：

1. 两账号、不同城市/年份、未标年份与空影集；重复副本、Unicode 多行文字、手动顺序、回收站原期限保留；恢复后重登、跨账号原图拒绝，默认新认证密钥与源密钥不同。
2. 源库各表、原图和会话不受快照整理影响；backup/restore 不复制认证密钥或暂存，已提交收据保持，原图哈希一致。
3. 快照时剔除已到期与 purging；恢复时截止前 1 毫秒、相等、截止后 1 毫秒；复制期间跨过期限的副本在完成前剔除，不重置期限，原备份仍保留其快照状态。
4. 剔除照片后重放原导入收据只返回原结果，不复活；未提交 receiving/staged 在副本中关闭，源批次与上传项不变。
5. 已提交内容仍位于真实 SQLite WAL 的情况，确认文字进入快照并成功恢复；空数据库也能备份、恢复并注册新账号。
6. 原图改字节/缺失、数据库损坏、清单数量不符、路径穿越、重复项、额外文件、额外 WAL、未知版本、缺失/布尔版本、重复 JSON 键均拒绝；恢复在验证失败时不创建目标。
7. 重算数据库哈希后，错误迁移版本、外键破坏和额外触发器仍拒绝，不把哈希匹配当作完整验证。
8. 缺失/损坏源原图、注入复制 OSError、最终校验失败：不报告成功，保留源资料和未完成标记；注入的私人异常文本、路径不输出。
9. 恢复时新副本删除失败保留未完成状态，不能启动；正常过期剔除只删除本次恢复新写的副本，原备份不变。
10. 已有目标、嵌套/祖先路径、缺失父目录和 Git 工作区目标被拒绝，不覆盖哨兵文件；真实硬链接和 Windows junction 被拒绝且源内容不变。
11. 维护锁同时阻止服务、在线迁移和第二备份；文件复制期间一直持锁，成功/失败后释放。
12. 真实子进程执行三条命令及服务运行时的互斥检查；恢复后的实际 Uvicorn 可启动，核对照片数量与字节。完整备份及未完成目录不能误作服务数据目录或执行在线迁移。

回收站时刻使用受控时钟，不是实际等待 30 天；磁盘/文件操作故障使用注入，不宣称模拟了真实硬盘坏块或所有断电情况。真实子进程验证命令、锁与服务启动；双账号登录/权限、文字顺序和旧 Cookie 失效另由真实 API 的 TestClient 验证。前端没有增加新页面或用例，48 项是既有流程回归，不计作 T11 新增测试。

原有两条 Starlette/httpx、BlockingPortal 弃用提示及前端终端颜色提示仍存在，不影响通过；本任务未升级依赖。

## 尚需落实的事项

- 真正使用前选择独立、受保护的备份介质，确认执行频率、保留份数、可接受损失时间和定期恢复演练；工具交付不等于已备份用户资料。同盘另一目录只能演练，不能防整盘故障。
- 备份含私人照片、文字和密码哈希，不内置加密；清单不是数字签名，不能证明来源可信。仅恢复自己掌管的可信备份。
- 全库恢复是快照状态，不合并后续改动，也无法知道后来才发生的删除。不能用旧快照推断新的回收站截止时间。
- 不自动清理历史备份、不支持跨版本自动迁移或损坏数据自动修复；目录清单与元数据有内存开销，真实大图/400/3000 规模及峰值性能留 T15。
- T12/T13 地图、T14 全产品、T16 本地完整交付及 T17 正式部署继续按计划，不因本次工具交付而提前标记完成。
