# T06 批量导入与重试验证记录

日期：2026-09-25。状态：已完成；使用临时数据库、临时账号与合成图片，不读取私人照片或本地生产数据。沿用 T04 的逐文件接收与提交协议，无新增依赖或数据库迁移。

## 交付内容

- 城市页与年份影集新增“批量导入原图”入口，原来的单张添加保留。
- 支持多选、逐项年份核对、未标年份、上下移动和移除；草稿每页 50 项。全都有有效编号时生成数字排序建议，混有无编号文件时保持选择顺序；人工调整后不会再次自动排序。
- `24-1.jpg` 按 2024 年第 1 张解释，两位年份范围 2000–2099，四位有效年份 1–9999。重复编号、重名及相同内容不自动去重。无法识别的城市导入文件必须人工指定年份或未标年份，不用当前年份兜底。
- 年份影集入口固定归属，包括“未标年份”；文件名年份冲突提示核对，不静默分流。
- 城市入口按确认后的年份分组，每组按顺序拆为最多 400 项的批次。先取得/创建对应影集，再调用相同导入 API。同影集的后批必须等前批保存或明确取消；其他影集失败互不回滚。
- SHA256 逐文件计算，不同时读入所有原图；上传最多两路并发。显示每项字节传输百分比及服务端校验状态，100% 不等于入库。上传完成后仍须点击保存。
- 支持单项重试、整队未完成项重试、停止传输后查询/取消。部分保存仅由本人点击“先保存成功项，放弃其余项”触发；失败项废弃，之后的新导入追加到末尾。
- 上传、创建和提交的网络重试沿用同一幂等标识；提交结果不明时重试保留原参数。影集版本冲突必须主动查询重新核对。
- 地址只保存随机队列 UUID。通过新增本人队列查询恢复服务端已登记批次；文件名、原图、哈希、凭据不写浏览器持久存储。未登记的文件不能恢复，未传完的文件需要重新选择；可多选匹配，同名同大小有歧义时逐行选择，最终由服务端核验内容。
- 过期批次在队列页可见，禁止上传/提交，可显式取消并清理本批未引用副本。完整自动回收、崩溃遗留临时文件及删除失败重试仍在 T10。

## 使用与恢复边界

城市/影集 → 批量导入原图 → 选择文件 → 核对全部归属和顺序 → 确认队列 → 上传 → 逐批保存。需要部分保存时点击带“放弃其余项”的明确按钮；已保存结果附有对应影集入口。

刷新只找回服务端已登记的部分。初始核对草稿、尚未登记的批次和本机文件引用不持久保存；切换账号/页面后可能需要重选。保留当前队列地址可继续查询。停止传输不是取消服务器暂存，结果不明先查询；接收租约尚有效时按提示稍后重试，不另造批次绕过幂等。

真实 400 张不同原图、3000 张账号、50 MiB 大图混合导入、峰值内存、硬件和长时间吞吐仍属 T15；本次微型重复内容的 401 项测试只验证协议和队列边界。文字、正式影集排序属于 T07；自动清理 T10、备份 T11、地图 T12/T13、上线 T17 未提前交付。

测试截图仅位于被忽略的 `frontend/test-results/`，不提交公开仓库。上传进度实现参考 [MDN XMLHttpRequest.upload](https://developer.mozilla.org/en-US/docs/Web/API/XMLHttpRequest/upload)：传输事件与最终服务端业务结果分开处理。
