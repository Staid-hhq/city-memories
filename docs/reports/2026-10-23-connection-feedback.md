# V2-04 子项 · 连接与启动提示

日期：2026-10-23。基线：操作反馈 `3c1b932`。本轮改善服务连接异常、启动帮助和会话核对，不把服务响应异常统一归因于用户网络。仅交付本子项，手机端细节、V2-04 整体验收、第二版整体验收及 T17 部署仍待安排；当前状态见[开发计划](../planning/development-plan.md)。

## 1. 问题与结果

前端原先在检查 HTTP 状态前直接解码 JSON。本地代理连接后端失败时可能返回空的或非 JSON 的 500 响应，JSON 解码错误会落到通用网络提示；非 JSON 的 401 也可能在执行登录过期清理前中断。本轮按 HTTP 状态和协议结果分别处理，保留结构化业务错误，不在页面展示原始代理响应或 HTML。

首次打开无法核对登录状态时，页面说明当前连接状态，提供手动重新连接和本机启动帮助。首次核对和已登录后的核对最多等待 15 秒；首次连接等待时可点击“重新连接”取消旧请求并重试，没有新增后台轮询或自动重连。页面标题区分“服务暂时不可用”“暂时无法连接城影记”“服务响应无法识别”和“连接等待超时”；帮助折叠在“查看本机启动步骤”，说明在 PyCharm 的“城影记－启动”核对前后端就绪，不替用户启动服务或仅凭失败确诊后端未启动。

已登录后回到窗口核对失败时，显示“暂时无法核对登录状态”及“重新核对登录状态”按钮，同一账号的暂时连接失败保留当前页面和未保存内容；核对成功清除提示，确认登录失效或换号时仍清除旧账号内容。退出处理中或退出失败时，不让窗口可见等会话检查重新显示旧账号，仍须明确完成退出。连接核对只读取会话，不自动重放上传、保存、删除或其他业务写入。原图查看层打开时保留原生模态焦点范围，先按原离开提醒正常关闭查看层，再使用顶层核对按钮。

具体页面操作见[使用指南](../guides/user-guide.md)，本机启动和排障见[本地手册](../guides/local-first-release.md#6-正常停止与常见问题)与 [PyCharm 指南](../guides/ide-startup.md#5-解释器与常见问题)。

## 2. 实现与更新

修改前端 HTTP 响应处理、顶层会话页和样式，沿用原认证接口、CSRF、请求取消和账号切换隔离。失败响应保留状态及业务错误，成功但协议不完整时返回 `RESPONSE_INVALID`；会话和登录用户另校验 `id`、`username`、`created_at`，登录还要求非空 CSRF 字符串，避免不完整成功数据进入私人页面。无新 API、依赖、锁文件或数据库迁移，不读取或升级用户真实数据库，不替用户启动或停止日常服务。

已完成 V2-01 数据库升级且已重启启用相册筛选/年份选项接口时，从 `frontend` 执行 `npm run build` 后在页面按 `Ctrl+F5` 即可，无须重启后端。此前尚未启用相册筛选接口时，仍按[相册查找记录](2026-10-23-album-library-filters.md)正常重启项目加载接口，不需要重复迁移。

## 4. 交付边界

重新连接或会话核对只验证服务和登录状态，不确认此前写入是否成功。业务操作结果不明时继续使用各操作的查询、核对和同参数重试规则；保留在页面内的草稿不等于持久保存，刷新、关页或确认退出仍按既有规则处理。

本轮不新增后台探活、自动重启、重复提交或启动脚本，不把 HTTP 状态作为数据库故障的确诊。服务无法完成启动时按现有指南查看对应运行窗口，不通过删除数据库、修改全局环境或重建私人资料解决。GitHub 仅同步源码与文档，不发布网站或备份私人资料。
