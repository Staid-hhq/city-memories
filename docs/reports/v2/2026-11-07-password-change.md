# 登录账号主动修改密码

日期：2026-11-07。基线：`7f349c9`。本轮为账号模块步骤 3，增加登录后的修改密码，不增加忘记密码找回、管理员重置或其他账号设置。

## 行为与实现

- 顶栏“修改密码”进入 `/account/password`，使用独立页面填写当前密码、新密码和确认新密码；手机账号入口独立成行，避免新增操作挤出屏幕。
- 当前密码仍接受 8–128 个 Unicode 码点，原样验证旧中文、空格及长密码。新密码/确认复用注册的 8–16 位可见 ASCII、有限弱密码校验，不能与当前密码相同，不改写输入。三个密码框独立显隐，支持键盘、粘贴、自动填充和密码管理器。
- 表单首次提交后标记全部本地错误，聚焦首错，编辑后重算依赖；精确状态/代码定位字段，服务和限流错误保留表单级。错误不回显原始凭据。
- `POST /api/v1/auth/password` 带 `expected_user_id`，仅与已登录会话身份比对，不据此选择用户。前端先核对 CSRF 和身份，后端在认证锁内重新鉴权；保留来源、CSRF、16 KiB 实际 JSON 边界。独立限流为每账号 10 次/15 分钟及每来源 30 次/15 分钟，成功也计入，超限提供 `Retry-After`。
- 当前密码验证及新哈希计算不持有数据库事务；与登录共用单实例锁，同一事务更新当前账号哈希并撤销其全部未撤销会话，成功 204 清当前 Cookie。其他账号、原图和影集不受影响；无数据库迁移或依赖变更。
- 整体操作等待上限 15 秒。预检失败且尚未发 POST 时保留输入并明确提示未提交；发出写请求后结果未知则清空密码、恢复隐藏、锁定表单，只提供“前往登录核对”，不自动重放，也不把当前匿名状态当成改密成功。
- 成功返回登录并明确提示已修改；未知、会话失效或换号返回登录使用各自提示。App 内存中的显式登录门禁阻止 visibility/pageshow/认证广播凭旧 Cookie 自动重显私人页，明确登录或登录结果核对成功才解除。整页重新加载仍按服务器当前会话核对，不把此门禁当持久凭据策略。

验证当前密码与敏感操作重新认证参考 [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#change-password-feature)，会话撤销参考 [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。具体新密码规则沿用本项目已确定范围，不将本轮描述成符合所有安全标准的认证验收。

## 更新与边界

本轮更新后须重启后端，并刷新已构建前端；无需迁移、重新建库或重置其他账号密码。密码哈希只在用户明确改密成功时变化。离线备份包含创建备份当时的密码哈希，恢复后使用备份当时的密码，不是使用新密码覆盖旧备份。

未运行构建版空库交付、重量级规模、真实手机及真实读屏软件专项；浏览器回归使用开发服务，生产资源另经 TypeScript/Vite 构建通过。跨设备撤销通过独立 Cookie 会话验证，未将同一浏览器的自动化结果称为真实多设备实测。尚未公开部署。
