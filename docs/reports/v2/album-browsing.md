## 2026-10-23 查找与排序

原报告：V2-04 子项 · 相册查找与排序。

日期：2026-10-23。基线：首页地图滚轮与边界光标修正 `4ff7252`。本轮按用户选择实现“我的相册”的城市、年份筛选及排序，保留已交付的首页侧栏和中国市级地图。V2-04 其余浏览细节、第二版整体验收和 T17 部署仍待安排，当前状态见[开发计划](../../planning/development-plan.md)。

### 1. 使用与返回

- 城市搜索支持城市名称或所属地区的文字包含匹配，输入后提交；服务端处理全部本人相册，不只搜索已加载卡片。
- 年份下拉提供“全部年份”“未标年份”及本人已有年份；选项来自所有本人相册，不受首 24 条、当前搜索词或筛选条件限制。年份与排序选择后立即应用，可与搜索组合；默认年份倒序、未标最后，也可选最近整理。
- 清除筛选恢复全部城市、全部年份和默认年份排序。无匹配时引导调整或清除筛选；从未创建相册时仍引导选城市创建，不混淆这两种状态。
- 切换条件先清旧结果并取消在途请求，迟到响应不覆盖新条件；失败重试保持条件。返回“我的相册”时保留同账号的条件、已加载数量和浏览位置，并按条件重读最新本人资料。
- 记忆只存在当前账号的 `Journal` 内存，不写入持久存储。退出/换号清理内容和请求，完整页面刷新后不承诺恢复筛选和已加载页数。相册详情、照片查看或导入后的返回来源保持原规则。

“最近整理”沿用首页的相册 `updated_at` 口径：创建、照片导入、移动、排序、回收/恢复及封面改变会更新，单独编辑照片文字不会更新。相册卡片、原图封面读取及原图字节保存规则不变。日常操作见[使用指南](../../guides/user-guide.md)。

### 2. 接口与实现

`GET /api/v1/me/albums` 仍返回 `{items, next_cursor}`，分页默认 24、最多 100，增加可组合条件：

| 参数 | 含义 |
| --- | --- |
| `q` | 最多 80 字符，去除首尾空白；城市名称或所属地区的字面包含搜索，空字符串无过滤；特殊字符不作为 SQL 通配符 |
| `year` | 省略为全部，`unmarked` 为 null，否则为 1–9999 的年份 |
| `sort` | `year`（默认）或 `recent`；沿用年份倒序/null 最后或更新时间倒序，稳定 ID 处理并列 |

过滤在当前账号范围内先执行，再应用排序和游标分页。无过滤兼容原年份/最近 scope；有过滤时签名游标绑定账号、排序、规范化搜索词和年份条件，不能跨账号或条件拼接页面。已有空影集也能被搜索，不按照片数隐藏。

新增需登录的 `GET /api/v1/me/albums/options`，返回 `{years: (number|null)[]}`：从本人的全部相册去重、数字倒序、null 最后；无相册返回空数组。它不接受列表搜索条件，也不泄露其他账号的年份。

前端沿用 [AlbumLibrary.tsx](../../../frontend/src/features/albums/AlbumLibrary.tsx) 和当前账号的 `Journal` 内存；后端沿用 [albums.py](../../../backend/src/city_memories/albums.py)。新增 [library-filters.spec.ts](../../../frontend/tests/e2e/library-filters.spec.ts)，归入默认四组回归最后的“首页与相册”组，继续用独立临时服务避免累计登录限流。既有业务、地图和连续流程分组保持。

## 2026-10-24 城市与年份层级

原报告：城市相册与年份影集层级（2026-10-24）。

本轮把“我的相册”改为一个城市一张相册卡，城市内保留多个年份影集框，再进入各年份的照片。属于 V2-04 浏览细节子项；V2-04 整体验收、第二版整体验收及 T17 部署仍待安排，当前进度见[开发计划](../../planning/development-plan.md)。

### 1. 页面与返回

- `/albums`：本人城市相册库。同一城市多个年份合并为一张卡，显示完整城市名、全部年份影集数及有效照片数，保留 3:4 封面与空封面状态。
- `/cities/{id}`：城市相册内的年份影集框。具体年份倒序、未标年份最后，空年份框继续保留，可打开原影集或继续创建、导入；不新建一份城市照片副本。
- `/albums/{id}`：既有年份影集照片页。返回时先回该城市的年份影集列表，再返回此前的相册库条件、已展开数量和位置；照片页入口沿用“返回某城市年份影集”文案。原图、导入等往返保留来源，首页“最近整理”仍可直达年份影集并返回首页。

相册库搜索仍按城市/所属地区匹配，年份筛选表示“包含该年份影集的城市”。卡片的数量、最新年份和封面仍取城市全部年份，进入城市后也显示其全部年份框，不因当前筛选只剩一个年份。首页统计及汇总文案区分“城市相册”和“年份影集”，不把年份框数量称为城市相册数。

同账号内存保留筛选、已加载数量与返回位置，资料变化时按原条件重读；完整刷新不承诺恢复此前内存。条件切换、退出或换号取消旧请求并清理相应私人结果；失败可原条件重试，无匹配与没有相册分别提示。

### 2. 聚合接口与数据边界

新增需登录的 `GET /api/v1/me/city-albums`，返回本人 `{items, next_cursor}` 城市分页，默认 24、最多 100；城市分组先于分页。每项白名单为 `city, album_count, photo_count, latest_year, has_unmarked, cover_photo_id, original_url`，有效照片只计 active，年份影集数包含空影集与未标年份。查询支持规范化城市/地区 `q`、具体年份或 `unmarked`、`sort=year|recent`、`cursor` 和 `limit`；游标签名绑定账号、条件与排序，并和旧年份接口隔离。完整字段、参数和排序契约见[数据与接口设计](../../architecture/data-api-design.md#城市相册聚合与筛选)。

默认城市排序以最新具体年份倒序、仅未标年份最后，最近整理以城市内最新影集更新时间倒序，同值按城市 ID 稳定排列。年份过滤仅决定城市是否入选；统计和封面不限制在该年份，空年份也可使城市匹配。

城市封面取最新有有效照片年份影集的封面，尊重该影集已有手选偏好，无效时回退该影集第一张有效照片；没有照片时为空。较新的空年份不会覆盖较早有照片年份的封面，不新增城市级封面偏好。原 `/me/albums`、`/me/albums/options`、`/cities/{id}/albums`、影集创建、导入、封面、照片整理与回收接口继续兼容。

城市相册只是既有年份影集的读取聚合，没有新增城市相册表、数据迁移、依赖或锁文件调整；不改影集/照片 ID、归属、原图字节、文字、顺序或历史导入收据。无需重新建立已有相册或重新导入照片。
