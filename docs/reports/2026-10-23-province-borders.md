# V2-04 子项 · 省市边界层级

日期：2026-10-23。基线：手机端细节 `c5a6a50`。本轮按用户要求在中国市级地图中增加省级界限，同时保留每个市的边界、本人照片填色和城市相册入口。仅交付省市边界层级子项，V2-04 整体验收、第二版整体验收及 T17 部署仍待安排；当前进度见[开发计划](../planning/development-plan.md)。

## 1. 问题与结果

此前全国地图中的市界均为浅色细线，省级分隔不易辨认。本轮在市界之上增加独立的灰绿色省界线，省界比市界略深、略粗；市界仍全部保留。缩放时保持线宽稳定，避免放大后边界过粗。

省界线只辅助阅读，不新增满屏省名标签、整省填色或省级相册。本人有效照片仍逐市填色，空影集不点亮；悬停说明、区域标题和无障碍名称包含所属省级地区、城市和本人照片数。点击或 Enter 进入城市相册，地图内滚轮缩放、桌面拖动、搜索定位、键盘和返回视角沿用现有规则。触摸默认滚动页面，明确开启“移动地图”后拖图；独立省界线层不拦截城市或地图的指针事件。

## 2. 公共数据与实现

省界使用现有 GeoCode-Release 固定提交 `6e3534f7af3675b19bd3c5d54c94022959dccdd2` 中同一公共 GeoPackage 的 `province` 线图层，按其 EPSG:4326、二维 `MULTILINESTRING` 声明读取，保留 **171 条源线、19,170 个顶点**。坐标量化到小数点后 5 位，不吸附、裁切、平滑或封闭线段。源下载 URL、SHA256 和解码规则继续由 [build-china-map-data.py](../../scripts/build-china-map-data.py) 固定，数据与许可说明见 [NOTICE](../../frontend/public/map-data/NOTICE.md)及 [LICENSES](../../frontend/public/map-data/LICENSES.txt)。

新线层存放在现有 [china-cities.v1.json](../../frontend/public/map-data/china-cities.v1.json) 的 `province_borders`，随应用本地加载。原 391 个已审核城市及同级目的地的面、定位点、背景面和 542 条国界/海岸/南海线保留，不重写业务 UUID 或注册新入口；草湖市仍待映射。城市目录和本人照片统计继续使用原有接口，没有新增在线地图请求、Key、API、依赖、锁文件或数据库迁移。

本省界来源为聚合线层，没有逐省名称或代码，不将 171 条线等同于 171 个行政区域，也不宣称已逐个核验 34 个省级区域的拓扑关系。省界与市界来自固定快照，精度可能略有差异，保留原线形；本轮不以视觉贴合为由改写区域几何，不宣称数据实时更新或已通过官方地图审查。

## 3. 本轮验证

- 环境：Microsoft Edge 155，前后端使用隔离端口 `5274/8174`、临时数据库与合成账号/图片，后端模块路径明确指向本次工作目录。纯模拟视觉预览只启动 `5275` 前端，所有 API 均拦截为合成记录，地图使用真实构建公共资产；不接日常服务。
- 公共资产：固定源哈希和二维 WGS84 元数据校验通过，两次离线生成字节一致。与基线逐字段比较，原 391 个区域的几何、定位点与目录信息、背景面和 542 条原线全部不变，仅新增省界及 revision。产物为 **5,478,006 字节**，SHA256 为 `12f17a9709911f625647e5d1160d715466354db617d2764d6761e36c80789310`；保留 171 条线、19,170 个顶点，其中 168 条开放线没有被封闭。schema 仍为 1，旧资产缺省界字段时兼容为空；无效省界数据拒绝加载。
- 静态检查：前端 `npm run build`、`npm run lint`、严格 TypeScript 检查、生成脚本 Ruff 均通过。无依赖或锁文件变更。
- 修复后回归：地图 **11 项**、首页 **3 项**、相册库及筛选 **6 项**，合计 **20 项全部通过，无跳过**。包含省界覆盖点击点时的区域命中、悬停所属地区及 0→1 真实照片数、滚轮/按钮/键盘、触屏滚页/移动切换、账号隔离和受控异步选城定位。构建版空库交付与连续照片流程 **2 项全部通过**。首轮完整默认 73 项的失败与修正过程见下；修复后按影响范围重跑上述检查，没有再次执行完整 73 项，也不将诊断阶段结果计作最终通过。
- 视觉：真实几何配合合成填色，复核 `1360×940` 全国、放大两级及徐州高倍视图，另查 `390×844` 触控布局；地图用例同时核对 `1024/360/320` 宽度无页面横向溢出。省界比白色市界清晰，城市填色及南海附图仍可辨认；省界不拦截指针，缩放时线宽稳定。源精度抽样的最大差异位于徐州附近一条仅 2 点的极短线，高倍可见微小几何，未见长段边界整体错位；继续保留源线，不人为吸附。
- 定位复核：三类响应延迟场景修复后，释放地图和足迹时目标可见比例为 1，再释放城市列表时约为 0.986（亚像素边缘差异）；真实滚轮主动回到页首后，两批迟到数据均保持 `scrollY=0`，没有抢回滚动。
- 仓库导航与差异检查通过：201 个已导航文件、627 个本地文档链接、79 个模块引用。公共原始下载、模拟配置、运行记录与截图均留在忽略目录，自建预览和测试进程结束后清理。

### 首轮失败与诊断

完整默认回归首轮为既有 **73 项中 72 项通过、1 项失败**，失败位于 `home-sidebar.spec.ts` 的“选择城市后目标位于视口”检查；不改代码原样定向复跑该文件，3 项全部通过。定向通过不足以说明首轮只是测试波动，随后继续检查异步布局时序。

诊断同时暂缓公共地图资产、`/me/atlas` 和 `/cities?q=` 响应，可确定复现：点击选城入口后，目标相对视口顶部约为 674.56px、`scrollY` 为 208；释放地图资产与本人统计响应后，目标顶部移到约 1339.58px，`scrollY` 仍为 208，视口交叉比例变为 0。原因是地图与城市手帐异步加载后撑高前方内容；初始页面较短，原先只在一次动画帧执行的锚点滚动受到当时最大滚动距离限制，后续布局增高没有补偿。

修复针对本次首页选城 hash 使用 `ResizeObserver` 跟随初始布局变化校正目标位置，在首次滚轮、触摸、指针或键盘操作时停止，避免继续改变用户主动选择的滚动位置。修复后的实际检查结果以本节最终记录为准；上述 3 项定向通过属于诊断阶段，不计为修复后验证，也不靠增加超时或降低视口断言消除失败。

首次修复后 20 项回归为 19 项通过、1 项失败，新的受控定位检查已通过；失败是另一既有侧栏用例点击退出后立刻整页导航到登录页，打断尚未完成的退出请求，页面仍是原合成账号，用户名输入等待超时。仅在该用例增加“确认已到登录页”再执行下一次登录的等待，没有修改应用退出逻辑、放宽断言或增加超时。最终重跑 20 项及构建版 2 项均通过。
