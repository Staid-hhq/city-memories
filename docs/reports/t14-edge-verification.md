## 发现的问题与修复

1. **实际布局问题：1024 宽页面多出横向滚动条。** 截图复查发现照片列表底部横向滚动条。根因是 `body` 固定 `min-width: 1024px`，而 Windows 非覆盖式纵向滚动条使可用宽度只有 1009px。旧断言用 `innerWidth`（包含滚动条），会错误放行；年份页还硬编码等于 1024。先加强断言复现：`scrollWidth - clientWidth` 实测 **15**，用例失败；移除固定最小宽度后同一用例通过，差值 **0**，截图无横向滚动条。未用隐藏横向溢出的方式掩盖内容。
2. **测试覆盖补齐。** 年份、批量、文字排序、移动、照片、回收站、地图共七处改为比较真实 `clientWidth`。新增完整 `journey` 流程，复用已有异常用例，不重写业务逻辑。
3. **测试运行与证据。** 新增 `CITY_MEMORIES_EDGE_HEADED=1` 可见模式；默认按业务、地图、连续流程三组启动独立临时服务，保持正式限流不变。截图分别写到 `frontend/test-results/group-1/2/3/`，后组不再清掉前组证据；全部已被 Git 忽略，关闭网络 trace，不提交截图、Cookie 或运行日志。
4. **换号测试时序竞争。** 回收站用例点击退出后立即由测试代码 `page.goto('/login')` 硬导航，偶发中断尚未完成的退出请求，新页面仍读到旧会话，导致等待登录输入框超时。改为等待应用确认退出并跳转登录页，再断言 `/auth/me` 返回 401 后登录另一账号；同样补齐两个地图换号用例的退出等待。没有用固定延时或放宽会话安全断言掩盖问题。

首轮新用例曾因回收站链接定位少了文件名而超时，已修正为准确的可访问名称，随后完整流程通过。布局修复后年份页旧断言曾把正确的 1009px 判成失败，也已统一修正。上述失败轮次及 15px 溢出的预期失败均不算最终全通过，不通过增加重试、跳过用例或放松断言处理。

## 复现

先正常停止自己运行的开发服务，留出 8000、5173 端口；测试拒绝复用已运行的服务，不自动结束其他进程。在 `frontend` 目录：

```powershell
# 仅当前终端；可见 Edge，仍然使用隔离测试数据。
$env:CITY_MEMORIES_EDGE_HEADED = '1'
$env:CITY_MEMORIES_LIVE_MAP = '0'
npm run test:e2e

# 只运行新增连续流程；这个单独调用也会创建新临时库。
npm run test:e2e -- tests/e2e/journey.spec.ts --output=test-results/t14-journey
```

不设置 `CITY_MEMORIES_EDGE_HEADED=1` 时仍使用同一实际 Edge 通道的无头模式；无需更换用户浏览器配置。`npm run test:e2e` 无参数走安全分组；显式传文件只执行指定组，不要将全部文件强行合并至一个服务后绕开正式登录/注册限流。后端验证仍在 `backend` 目录运行 `uv run python -m pytest -q`、`uv run ruff check .`。
