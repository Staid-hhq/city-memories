# 此间集 · 产品需求与验收标准

2026-11-24 · 前端重构第一阶段 · 待原型评审与实现验收

## 这次要解决什么

此间集服务于自己和少量朋友，每个人保存自己的旅行原图，按城市、年份和手定顺序回看。打开应用时，有人想找“我在哪些城市留下过照片”，也有人已经知道要翻哪本相册。

目前登录后就进入中国地图，页面同时出现选城、相册和个人统计。想直接翻相册的人也会触发全国地图加载。用户反馈首屏内容杂、等待影响体验。**本轮目标是让用户打开首页就能选择去向，点「全部相册」的人全程无需等地图。** 先完成前端入口和浏览流程，再根据实际需要安排后端工作。

## 首页与两个入口

| 位置 | 用户在这里做什么 | 页面要求 |
| --- | --- | --- |
| 首页 | 选择按地点回看，或直接翻相册 | 主内容只放「中国地图」「全部相册」两张功能卡，每张卡整块可点。卡名最醒目，可配一幅静态图形和至多一句用途说明。桌面并排，窄屏纵排。账号、回收站等管理操作放在次级导航。 |
| 中国地图 | 看哪些城市存有自己的照片，从地点找回忆 | 进入地图页才加载地图。只点亮本人有有效照片的城市，选中城市可打开它的年份影集。加载时有反馈，失败时可重试，也可直接去相册。 |
| 全部相册 | 认封面、搜城市或筛年份，找到想看的照片 | 直接展示本人的城市相册。点城市看年份，再点年份看照片。已有相册和新账号空态都提供文字选城、创建影集的入口，选城可独立于地图使用。 |

首页卡片只负责带人进功能页。城市清单、统计和相册封面放在对应页面。两张卡可分别用简化地图和叠放相片的图形来区分，保持一致的边距、标题层级和焦点样式。原型评审看桌面、窄屏各一张首屏图，重点看两项选择是否一眼可辨。地图页和相册页各有独立地址，后续调整卡片名称、顺序或外观时，可以单独验收首页。

## 照片按什么归档

首轮沿用「城市相册 → 年份影集 → 照片」。地图与全部相册打开同一份资料。相册与年份由本人选择，原图即使缺少定位和拍摄日期也可以归档。

| 用户的情况 | 本轮规则 |
| --- | --- |
| 春天和秋天各去一次杭州 | 两次都选「杭州 · 2026」时，照片进入同一本年份影集。新加入的照片排在末尾，原有手动顺序保留。 |
| 同一趟行程先去杭州，再去苏州 | 两地照片分别放入本人选定的城市和年份。从地图、相册进入，都能找到同一批照片。 |
| 想先建影集，或记不清年份 | 可先建空影集。年份未知时可选「未标年份」，排在具体年份之后。同城重复创建同一年份会打开已有影集。 |

按一次旅程浏览也有价值，尤其适合同年多次去同一城市或跨城市出游的人。本轮优先解决打开应用和找相册的体验，已有资料可以原样使用。以后若常常想按“那一次旅行”找照片，再评估可命名、可跨城市的旅行相册。

## 怎样验收前端

以下均为**待执行**场景。使用 Edge 和两个测试账号。一个是新账号，另一个在一座城市有两个年份的合成照片，在另一座城市只有空影集。用禁用浏览器缓存的新页面验证首次访问，地图故障测试只阻断地图专用请求，保持账号和相册服务正常。

| 编号 | 实际操作 | 通过条件 |
| --- | --- | --- |
| AC-01 首页好辨认 | 分别以桌面（1280 × 800）和窄屏（375 × 812）打开首页。请一位未看过原型的人先找“去过哪里”，再找“已有相册”。 | 两张主卡均在首屏，测试者每次首次点选就进入对应页面。窄屏无横向滚动。用 Tab 可依次看清两个焦点，用 Enter 可分别进入对应页面。 |
| AC-02 相册不等地图 | 在已登录状态下禁用缓存，首次打开首页，停留并进入全部相册。另开新页面直接访问相册。查看两条路径的网络记录。 | 从打开到相册可操作，全国几何数据与地图专用城市接口均为 0 次请求。能直接查看本人相册或新账号空态。现版对应请求为 `/map-data/china-cities.v1.json` 与 `/api/v1/map/cities`。 |
| AC-03 地图按需加载 | 从首页点地图，延迟响应，在等待时返回首页进相册。再阻断地图请求，重新进地图，看到失败提示后解除阻断并点重试。 | 进入地图才发起地图请求。等待中可离开，失败后能重试或去相册。重试成功可选城，有有效照片的城市点亮，只有空影集的城市保持未点亮。 |
| AC-04 第一本影集 | 阻断地图请求，用新账号从全部相册空态选城、创建年份影集，再导入一张无定位信息的合成照片并确认保存。打开旧选城书签 `/#choose-city-title`。最后解除阻断，进入地图。 | 空态和旧书签都能到达可操作的城市选择。地图不可用期间，空影集可以创建，保存后可从相册库打开原图。恢复地图后，该城市点亮。 |
| AC-05 回到刚才的位置 | 在全部相册筛年份，打开某城某年并查看原图，再逐级返回。另从放大后的地图进同一城市再返回。直接刷新已有城市或年份影集地址。 | 两条路径看到同一照片及文字。逐级返回时相册保留本次筛选和浏览位置，地图保留本次视角。已登录用户刷新原有城市、影集地址仍打开对应内容。 |
| AC-06 旧资料和账号隔离 | 用重构前已建的合成资料，分别从两个入口查看原图、顺序和文字。以另一账号登录，尝试打开前一账号的影集和原图链接。 | 原账号已有照片可直接浏览，数量、归属、顺序和文字与原记录一致。另一账号只看到自己的相册及点亮状态，也无法读取前一账号的私人链接。 |

验收记录应附两种尺寸的首页截图、两条冷启动路径的网络记录和逐项结果。若仍觉得首页慢，记录从打开到卡片可操作的时间、设备与网络条件，用于定位下一步改进。是否达到视觉预期以原型评审为准。

## 贯穿重构的产品约定

- **原图与导入**　从电脑或 U 盘选择照片，确认保存后可移走源文件并重新打开原图。保存的字节与源图一致。文件名编号只辅助核对，重复照片由本人决定保留哪份。失败的导入须显示失败，保留重试途径。
- **整理与恢复**　照片移动后保留原图和单张文字。手动排序可在重启后恢复。回收站保留 30 天，恢复后照片回到原影集。备份与恢复须能还原照片归属、原图、顺序与文字。
- **使用环境**　优先验收电脑端 Edge，窄屏核对首页的浏览与操作。首轮使用现有本机服务。公开部署和跨电脑访问继续按 T17 单独验收。

当前版本的操作和异常处理见[功能使用指南](../guides/user-guide.md)，接口与数据规则见[数据与接口设计](../architecture/data-api-design.md)，交付状态见[开发计划](../planning/development-plan.md)。

## 设计参考与历史依据

- Apple 照片允许用户主动打开地图按地点浏览，也提供按一次旅程回看的入口。这两种查找方式帮助区分了“去过哪里”和“哪次出游”。[按位置浏览照片](https://support.apple.com/zh-cn/guide/iphone/iph390138909/ios) · [查找旅程照片](https://support.apple.com/zh-hans/guide/iphone/iph7cce5d7a2/ios)
- Google 相册支持为相册命名和指定封面。此间集借用以名称和封面辨认相册的做法，首轮使用已有城市名和封面。[创建和编辑相册](https://support.google.com/photos/answer/6128849?co=GENIE.Platform%3DDesktop&hl=zh-Hans)
- 第一版 R-21 曾要求“地图是首页主体”。本轮由功能卡首页取代该条。首轮卡片数量和暂缓旅行分组是此次重构的产品取舍。旧版其余规则和任务编号仍可追溯。[第一版需求与验收原文](https://github.com/Staid-hhq/city-memories/blob/c435dacba522a426b7d6eefbc0e38e063ce90720/docs/product/requirements.md)
