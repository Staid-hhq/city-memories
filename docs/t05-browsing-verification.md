# T05：照片列表与原图查看交付记录

日期：2026-09-25。状态：已完成。对应 [开发任务 T05](development-plan.md) 与 [照片接口契约](data-api-design.md#5-城市影集与原图接口)。复用原有数据库、私有原图和依赖，无新迁移、密钥或外部服务；不修改用户照片。

## 已交付的使用流程

1. 从自己的城市年份影集进入照片列表，每次读取 24 条资料，按保存顺序排列；点击“加载更多照片”继续。
2. 图片与年份封面直接读取鉴权原图。只有视野附近的图片发起请求，远处保留尺寸稳定的占位，既不一次读取所有原图，也不生成缩略图文件。
3. 点开照片后适应窗口显示完整画面，显示文件名、原尺寸、大小和当前位置；前后按钮及左右方向键可跨过尚未加载的列表页，首尾按钮明确禁用。
4. Esc、“关闭原图”或浏览器返回关闭查看层，恢复本次打开时的列表滚动位置与按钮焦点；已读分页不丢失。查看地址带 `?photo=<UUID>`，刷新后仍可读取当前照片，但不持久保存整个列表和滚动历史。
5. 上传成功后列表与数量更新，可通过“查看刚保存的照片”直接打开新图，即使它不在首批 24 条内。加载失败显示重试，空影集只在成功读取为空时展示。

后端新接口在 `backend/src/city_memories/photos.py`，前端为 `PhotoGallery.tsx`、`OriginalImage.tsx` 及影集接入。原图字节接口复用 T04；文字仅展示已有纯文本，编辑/排序在 T07。

## 关键实现边界

- 分页签名绑定账号、影集、影集 revision、上一项 position/id；归属、版本、列表及数量来自同一数据库读取快照。篡改/跨范围游标拒绝，资源归属先行检查，其他账号与不存在均为 404。
- 详情前后 ID、序号、总数来自本影集全部有效照片，排除回收站；可传 album_id 和 expected_album_revision 检查浏览上下文。新导入改变版本时返回 409，不让旧页继续与新页混用。
- 续页普通网络失败保留已读项并可重试；版本冲突要求明确重新加载首批新快照。查看层的“重新核对照片”重新取得当前版本，不自动接受过时的前后关系。
- 原图通过同源 Cookie、no-store fetch 读取，当前页面最多两个原图传输，排队请求也可取消。视野范围是上下各 160px；离开视野、切换照片、关闭页面或退出时取消相应读取并释放 Blob URL。查看层打开时暂停列表图片，只加载当前原图。
- 图片读取和 JSON 共用会话代次/退出取消机制；原图 401 也使私人页面退出。Blob URL、完整照片资料不进入 localStorage/sessionStorage；其他账号无法通过已有照片 UUID 读取原图。

按需卸载能限制同时保留的图片数量，不保证浏览器立即归还全部进程内存。原文件先完整传入 Blob 后显示，不是流式渐进解码；大图、带宽和内存峰值仍待 T15 实测。当前保持单实例、本机 HTTP，不视为互联网部署或生产规模验收。

执行命令：

```powershell

.\.venv\Scripts\ruff.exe check .
.\.venv\Scripts\python.exe -m pytest -q

npm run lint
npm run build
npm run test:e2e
```

本机应用程序控制阻止 `pytest.exe` 独立启动器，改用同一项目 Python 的模块入口完成验证，没有重装包或更改系统策略。后端有两条既有 Starlette/httpx、AnyIO 弃用警告；测试通过，未为提示改锁文件。

截图只含合成资料，位于被忽略的 `frontend/test-results/`，不提交 GitHub；不记录含凭据的网络 trace。测试服务由测试流程启动和停止，不复用私人数据库或常驻实例。
