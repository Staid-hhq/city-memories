# 城影记开发任务拆分

日期：2026-09-26。阶段 7 工作基线，依据 [技术方案](tech-stack.md)、[数据与接口设计](data-api-design.md)、[需求](requirements.md) 和 [页面与流程](page-flow.md)。各任务实施记录见本文末尾。

下面的“批次”是正式开发的实施顺序，不是新增的准备阶段。T01–T07 已完成；T12 待核查、T17 待安排，其余任务按依赖推进。原型与设计检查的已有结果另行保留。

## 1. 按六个批次交付

| 批次 | 目标 | 用户可以验收的结果 |
| --- | --- | --- |
| 1. 基础与账号 | 搭建正式工程，接入真实账号和数据库 | 能注册、登录、退出；两个人的数据隔离，重启后账号仍在 |
| 2. 影集与原图 | 贯通最小的照片保存流程 | 选城市、建年份影集、保存一张原图、重新打开查看；源文件移走不影响副本 |
| 3. 批量与整理 | 完成日常导入、文字、顺序与移动 | 批量添加、按自己的顺序整理、写文字、跨城市或年份移动，自行处理重复照片 |
| 4. 回收站与备份 | 完成删除、恢复、到期清理及数据恢复 | 误删可恢复；清理不影响其他照片或源文件；能从备份恢复资料和原图 |
| 5. 正式地图 | 将新版地图接上真实账号资料 | 当前账号有照片才点亮城市范围，浅省界、城市点击、搜索和返回视角正常 |
| 6. 验收与交付 | 验证 Edge、规模、失败恢复，整理启动说明 | 本地第一版可运行、可维护；另列上线前条件，不把本地地址当成公开网址 |

每次实施一个任务或一组紧密相关的任务，完成对应接口、页面与必要检查后再继续。学习说明随任务提供，重点解释当前功能的数据流和实现选择，不先把全部后端或全部页面堆完。

地图完整性、数据使用条件和首次加载约一分钟的问题有外部依赖，T12 的核查应在前期穿插开展；正式地图页面接入仍放在第 5 批。核查遇到问题可以继续账号和影集开发，但不能因此把地图验收标为通过。

## 3. 每批如何验收

| 批次 | 必要检查 | 本批完成后仍需明确的边界 |
| --- | --- | --- |
| 1 | 构建和迁移；两账号注册登录、退出、CSRF 与会话失效 | 还没有照片保存功能；不能以页面能打开宣称账号隔离全部通过 |
| 2 | 少量人工生成图片的保存前后哈希；移走测试源；重启后读取；跨账号原图拒绝 | 单张闭环已通，批量与真实规模未验收 |
| 3 | 故意打乱上传完成顺序；丢失提交响应再重试；分页排序、文字绑定、并发冲突；跨影集移动 | 重复删除完整流程需与第 4 批一起验收 |
| 4 | 可控时间测试 30 天期限；恢复/清理竞争；空间或文件操作失败；新目录恢复备份 | 不用真的等待 30 天；测试不在用户原图目录运行 |
| 5 | 实际 Edge 地图视觉、点击、缩放与返回；两账号点亮差异；新增/删除/恢复联动；异常网络 | 地图性能、完整性或外部条件未解决时保持未通过，不靠静态截图替代真实接入 |
| 6 | 完整关键流程、400/3000 规模、多账号读写、可复现启动与交付记录 | 本地通过不等于互联网传输、正式域名或跨电脑访问通过 |

每项检查只在对应功能具备后执行；修复问题后复查受影响范围。本文本轮仅做计划结构与链接检查，不重复原型 Edge 测试、25 项 SQL 设计检查或已有图片验证。

性能测试先固定样本与环境，记录首批资料时间、首张原图时间、排序/文字响应、内存峰值及重复进出页面后的变化。初始本机目标：在单账号测试集下，首批资料和文字/排序请求的 p95 各不超过 1 秒；这是待实现后验证的工程目标，不包含大原图网络下载，也不构成互联网体验承诺。全量地图可用时间单独记录，现有约一分钟的问题必须在 T12 提出改进方案，在 T13 验证并交用户审阅。

测试样本不足时可以使用不同内容的合成图片，但必须标注；不能重复使用少量文件就声称真实 3000 张照片已通过。网络原图体验有问题时先排查加载范围和并发，保留原图及不生成预览图的已确认规则；需要改变该规则时再讨论。

## 4. 每个任务的交付记录

实施时使用同一种简短记录方式：

- 状态：待开发、开发中、待验证、已完成，或注明具体阻塞。
- 修改：解决了什么问题，涉及哪些文件和接口。
- 验证：实际通过的检查、未执行的范围、使用的样本与环境。
- 遗留：影响、下一项任务和是否阻止当前批次完成。

任务的代码、界面和必要验证全部满足完成标准后才记为已完成。修复不能丢弃已有原型或用户改动；文档与实现出现差异时先修正到同一规则，避免前后端按不同约定继续开发。
