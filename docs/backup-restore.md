# T11 · 一致备份与恢复操作说明

更新：2026-10-03。适用于当前备份格式 v1、数据库迁移 `b61e24f803a7`。命令从项目 `backend` 目录运行。此工具不提供网页入口，不上传照片，不自动安排定时任务。验证结果见 [T11 交付记录](t11-backup-verification.md)。

## 先理解范围

备份保存快照时的账号（含密码哈希）、城市、空影集、有效照片、未到期回收站、文字、顺序、版本和已提交导入收据，并复制对应独立原图。照片 ID 和字节不变，同内容的每份照片分别保存，不去重。

不复制 `.env`、认证密钥文件、源 U 盘、上传暂存文件、purging、快照时已到期照片；快照副本中的旧会话、限流记录被清空，未提交批次关闭为 canceled、未提交项置 discarded。**这只改变备份副本，不取消源库中的导入、不使源服务账号退出，也不删除源照片。** 恢复后未保存的导入需重新开始，不能把暂存当成已保存照片。

备份包含私人照片、原文件名、文字、账号和密码哈希，**并非匿名数据，也没有内置加密**。只存放在你控制、访问受限的独立介质上，不放 GitHub、公开网盘目录或前端静态目录。校验哈希用于发现损坏，并非数字签名；只恢复自己掌管的可信备份，不能把它当作任意第三方数据库的安全检查器。

同一块硬盘上另一个目录只适合演练，不是独立介质备份。本工具不能验证两个盘符是否属于不同物理硬盘，也没有替你选择备份频率、保留份数或可接受的数据损失时间；正式使用前需落实这些安排。

## 1. 准备维护窗口

1. 在页面核对已保存结果；把需要保存的上传明确提交。暂存进度到 100% 不代表保存成功。处理未保存文字，通知其他使用者暂停使用。
2. 在后端终端按 `Ctrl+C`，等待 Uvicorn 正常退出；使用 `--reload` 时也要停止重载父进程。不要强行结束正在保存的进程，不要手工删除 `maintenance.lock`。前端可以停止或保持，但后端停机期间不可读写。
3. 选已存在的本地父目录，保留足够空间容纳数据库、全部有效原图、未到期回收站及数据库整理临时空间。备份和恢复的最终目录必须**尚不存在**；不能与来源相同、互相嵌套，也不能放在任何 Git 工作区里。不支持网络共享、符号链接、junction 或硬链接。

工具全程持有与应用相同的操作系统锁，其他服务、清理、在线迁移或维护命令不能同时进入同一数据目录。服务未停会返回 `MAINTENANCE_BUSY`，不会擅自停掉服务。这个维护窗口暂时停止所有后端访问，而非在线不停机备份。

## 2. 创建并校验备份

以下路径仅为示例：请把 `E:\CityMemoriesBackups` 换成实际独立介质上的、已经创建好的私人父目录；把 `--data-dir` 换成正在使用的数据目录。**不要原样执行不存在的盘符，也不要仅按项目默认目录猜测真实数据位置。**

```powershell
# 在 D:\Workspace\city-memories\backend 运行；后端须已正常停止。
uv run python -m city_memories.backup create --data-dir 'D:\Workspace\city-memories\.local-data' --destination 'E:\CityMemoriesBackups\2026-10-03-01.cmbackup'
if ($LASTEXITCODE -ne 0) { throw '备份未完成，请先排查，不要继续恢复' }

uv run python -m city_memories.backup verify --backup 'E:\CityMemoriesBackups\2026-10-03-01.cmbackup'
if ($LASTEXITCODE -ne 0) { throw '备份校验未通过' }
```

已创建过的目录不会被覆盖或合并。下一次备份使用新的名字，不要为了重试删除上一份好备份。

成功输出一行 JSON：`status: ok`、操作名称、账号数、影集数、有效/回收站照片数与原图总字节数。退出码 0 才是成功；1 表示维护失败，2 为命令参数错误。输出不含文件名、路径、账号或密钥。创建命令已内部完整校验，`verify` 可在以后或介质复制后再次检查。

目录内容为：

- `backup-manifest.json`：格式、迁移版本、快照 Unix 毫秒时间、各表数量、数据库大小和 SHA256、逐份照片大小/哈希及元数据摘要。
- `database/city-memories.sqlite3`：通过 SQLite Backup API 获取并整理的完整快照，包含已提交的 WAL 内容，不依赖额外 WAL/SHM 文件。
- `originals/<系统存储键>`：每份照片的独立、原字节副本。
- `maintenance.lock`：操作系统锁文件，保留是正常情况。

不增添、编辑或重命名备份内成员。校验会核对目录成员、版本、数据库完整性及外键、清单与实际照片关系、大小和哈希；缺文件、额外文件、错哈希、未知版本、链接或未完成标记都不会通过。工具不会修复损坏备份或自动删除坏副本。

备份完成后，可按原启动命令恢复**原数据目录**的服务；自动清理也随服务恢复。备份截止时间取维护快照时刻，长期备份过程中跨过期限的照片在恢复时仍会重新核对，不重新计算保留期。

## 3. 恢复到全新目录并检查

即使是故障恢复，也不覆盖现有资料，不向现有库合并。优先保留当前目录和原备份，在 Git 工作区外选择一个尚不存在的新目录；其父目录需已存在。例如 `D:\CityMemoriesRecovery` 仅作为新目录恢复演练位置，不是独立备份介质。

```powershell
uv run python -m city_memories.backup restore --backup 'E:\CityMemoriesBackups\2026-10-03-01.cmbackup' --destination 'D:\CityMemoriesRecovery\2026-10-03-01.cmrestore'
if ($LASTEXITCODE -ne 0) { throw '恢复未完成，不要启动该目录' }
```

恢复先完整验证备份，再写新目录；结束前复查关系、原图、文字/顺序元数据摘要和期限。已到期回收站不进入可用结果，复制期间刚到期的副本也会移除，成功输出 `expired_excluded` 数量；原始 `purge_after` 不延长。服务启动和每次读取仍按当前服务器时间检查期限。系统时间早于快照时间会拒绝恢复，请先核对时钟。

所有旧登录会话失效，使用原用户名和密码重新登录；密码哈希保留，不重置密码。认证密钥和运行配置不从备份复制：默认在新目录首次启动时生成新密钥；若已有环境变量注入认证密钥，仍采用你的运行配置，但旧会话仍然失效。未提交导入关闭、原幂等收据保留，重放收据不重新生成已剔除的照片。

先停止旧后端，再在专用终端临时指定新目录运行检查：

```powershell
# 只影响当前终端；不要把配置或恢复数据提交到 Git。
$env:CITY_MEMORIES_DATA_DIR = 'D:\CityMemoriesRecovery\2026-10-03-01.cmrestore'
uv run uvicorn city_memories.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

不用先在备份或恢复目录运行 Alembic；本工具要求当前兼容版本，完整快照已有表。备份目录禁止直接作为应用数据目录启动或迁移。运行期间不要再次启动旧实例、编辑数据库或直接操作原图目录。

通过前端重新登录后，核对各账号城市/年份归属、空影集、数量、文字、顺序、重复副本及未到期回收站；查看几张原图；确认旧 Cookie 无效、另一个账号不能读取这些照片。之后停止检查服务，再决定正式使用哪个数据目录。恢复测试会生成新会话或触发到期清理，但不会改动原备份和旧数据目录。

恢复的是**快照时的状态**，不包含备份之后的新增或修改，也无法推断后来发生的删除；旧快照中仍为 active 的照片会按快照恢复。这个限制与“快照里已知的回收站期限不得重置”是不同的问题。选择备份前先确认日期，不把全库恢复误当成合并或撤销单次编辑。

## 4. 失败与保留策略

- `MAINTENANCE_BUSY`：正常停止后端、迁移或其他维护命令，等待其退出再重试；不能靠删除锁文件绕过。
- `DESTINATION_EXISTS` / `OVERLAPPING_PATHS` / `PUBLIC_WORKSPACE`：换一个 Git 工作区外、与来源无包含关系的新目标；不使用覆盖选项，本工具没有强制覆盖模式。
- `CHECKSUM_MISMATCH` / `SOURCE_MISMATCH` / `INVALID_BACKUP`：文件或关系不一致，保留源数据和好备份，排查介质与版本；不要修改清单“让校验通过”。
- `SCHEMA_MISMATCH`：使用与数据版本匹配的工具；本次不做跨版本自动迁移。
- `MAINTENANCE_FAILED`：检查完整性、磁盘空间、权限和占用。错误文本刻意不输出原始异常/路径，避免私人内容进入日志。

失败或中断可能留下新目标及 `.maintenance-incomplete` 标记，包含部分私人资料；**不得删掉标记强行使用**。应用和迁移都会拒绝这些目录。重试选新名字，确认保留好备份后再人工处理失败副本；工具不递归删除任何目录，也不自动重试或恢复半成品。

当前校验/恢复会打开备份中的操作系统锁，因此备份目录与锁文件须可访问并允许相应锁操作；若介质以只读方式挂载导致锁失败，先复制完整备份到受保护的可写演练位置，再重新校验。保留原介质不动。

工具不会自动删除历史备份、轮换份数或同步异地；自动清理只作用于正在使用的数据目录，不会擦除历史备份。正式使用前确定执行频率、独立介质、访问保护、保留周期和定期新目录恢复演练，后续部署在 T17 落实。不宣称已完成大规模、真实断电或硬盘损坏恢复测试。
