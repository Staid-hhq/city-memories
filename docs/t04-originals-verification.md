# T04：单张原图持久保存交付记录

日期：2026-09-22。状态：已完成。对应 [开发任务 T04](development-plan.md)，遵守 [导入协议](data-api-design.md#6-导入协议与失败恢复)。本任务不需要用户提供真实照片、密钥、域名或额外服务。

## 交付内容与使用

进入自己的城市/年份影集，选择一张 JPEG、PNG 或静态 WebP，点击“上传并校验”，确认城市和年份后点击“保存到影集”。“已传输，待保存”不计入照片数；只有原图就绪、照片资料和收据事务提交完成，才显示“已加入影集”。当前可显示本次保存或影集首张原图，完整列表和前后张浏览留给 T05。

- 单文件上限 50 MiB、8000 万像素；没有缩略图、转码、压缩或自动去重。相同文件主动再次添加，保留独立照片 ID 和存储副本。
- 浏览器读取所选文件计算 SHA256；服务端重新核验实际字节、哈希、格式、帧数及解码结果。原文件名仅用于展示，磁盘路径仅使用服务端随机标识。
- 沿用批次创建、逐项上传、查询、提交和取消协议，未新增一次性上传接口。接收前检查归属和 CSRF，解析过程中限制真实请求体，不信任 Content-Length 或上传 MIME。
- 文件发布在数据库写事务外；照片、上传状态、影集版本和幂等收据在短事务内一起提交。数据库失败时保留未引用的系统副本供同批次重试，不生成可见的无原图记录。
- 访问原图必须是当前登录账号的有效照片；跨账号统一 404，未登录/旧会话 401。私人响应 no-store、nosniff，不暴露 storage_key、完整哈希或磁盘路径。
- 页面地址携带非凭据的批次 UUID，刷新可查询已暂存/已保存结果；未传完需重选原文件。取消尚未提交项不动源文件、既有照片或其他导入；结果不明可查询和重试，不自动重建照片。

代码：`backend/src/city_memories/imports.py`、`storage.py` 与现有授权/错误边界；`frontend/src/UploadPanel.tsx`、影集页及样式。复用既有表和锁定依赖，迁移版本仍为 `b61e24f803a7`，无需新配置。

50 MiB 用例是有效小 PNG 后附零填充，只验证真实文件体量和原字节保留，不代表大分辨率解码/性能测试。8000 万像素边界未用真实大图跑满；400 张不同原图、单账号 3000 张、多账号大规模读写仍在 T15。

Edge 新增流程：

1. 合成 720×420 PNG → 暂存仍为 0 张 → 刷新恢复 → 确认保存为 1 张 → 原图 SHA256 一致 → 重载可读 → 另一个账号 404、退出后 401。
2. 让真实上传/提交完成后故意丢弃响应 → 页面重试仍只有一张 → 用户主动再添加同文件得到第二个独立 ID。
3. 假图片失败 → 取消不增加数量 → 暂存后取消 → 模拟 409 提示需重新核对，再提交成功。真实数据库版本冲突另由后端测试覆盖。

## 实现约束与后续

当前只支持一个后端实例。每次接收租约 15 分钟，全局最多同时解析/解码两张，同批最多两项接收。批次未提交 24 小时过期；到期即拒绝上传/提交，重启把中断的 receiving 项转为可重试失败，绝不自动加入影集。

取消会尝试清除本批未引用的系统副本；删除失败、崩溃遗留 `.part`/未引用原图、过期行等的全面核对与定时清理仍属于 T10，当前可能占用额外磁盘空间。已提交幂等收据不清除。保存原图与数据库不是同一个文件系统事务，不能把此次进程重启/故障注入测试称为物理断电或磁盘损坏恢复验证。

下一项为 T05 完整分页列表、按需读取、前后张与返回位置；T06 增加批量 UI、进度和进行中的取消；T11 提供独立备份恢复。当前是本机 HTTP 开发环境，没有公开部署；GitHub 仅同步源码和文档，`.env`、认证密钥、数据库、原图、暂存及运行截图均保留本地。

实现依据：已核对 [Pillow Image 校验/解码接口](https://pillow.readthedocs.io/en/stable/reference/Image.html)、[FastAPI 文件上传说明](https://fastapi.tiangolo.com/tutorial/request-files/)，并检查已锁定版本 Starlette 的解析器实现；本项目额外在 multipart 解析前做权限检查并限制实际字节。
