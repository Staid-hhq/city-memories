# 此间集 · 产品需求与验收标准

2026-11-27 · 前端重构第一阶段 · 待原型评审与实现验收

## 这次要解决什么

此间集服务于自己和少量朋友，每个人保存自己的旅行原图，按城市、年份和手动设定的顺序回看。打开应用时，用户可能想看哪些城市存有照片、翻一本已有相册，或把刚带回来的照片放进去。

目前登录后就进入中国地图，页面同时出现选城、相册和个人统计。想直接翻相册的人也会触发全国地图加载。用户反馈首屏内容杂、等待影响体验。**本轮目标是让用户从首页直接选地图、翻相册或添加照片。翻相册和添加照片都无需等待地图。** 先完成前端入口和使用流程，再根据实际需要安排后端工作。

## 首页的三个入口

| 位置 | 用户在这里做什么 | 页面要求 |
| --- | --- | --- |
| 首页 | 选择浏览方式或开始记录 | 标题旁放「添加照片」按钮，下方放「城市地图」「我的相册」两张可整块点击的浏览卡。桌面两卡并排，窄屏纵排。账号、回收站等管理操作放在次级导航。 |
| 城市地图 | 按地点找照片 | 打开后才加载中国市级地图。只点亮本人有有效照片的城市，选中城市可打开它的年份影集。加载时有反馈，失败时可重试，也可直接去相册。 |
| 我的相册 | 认封面、搜城市或筛年份，找到想看的照片 | 直接展示当前账号的城市相册。点城市看年份，再点年份看照片。已有相册和新账号空态都提供文字选城、创建影集的入口，选城可独立于地图使用。 |
| 添加照片 | 把新照片放到对应城市和年份 | 从首页直接选城、选照片，核对年份和顺序。上传时按确认的年份创建或复用影集，用户明确保存后可在影集中查看原图。新账号可直接添加第一张照片，无需预建影集。 |

三个名称沿用现有主导航和导入入口的用词。首页相册卡用一张轻量街景封面提示摄影内容，地图卡用静态街区示意提示按地点浏览。标题和入口在图片加载期间即可操作。账号的城市清单、统计和相册集合放在各自的功能页。

相册页用城市名、年份和照片数组织版面。界面采用低饱和底色，照片保留原色。封面可以裁切，打开单张时横图、竖图都应完整显示。零照片的影集显示空封面和添加入口。局部磨砂用于照片上的操作控件等悬浮层，明亮照片、暗色照片以及关闭透明效果时，都要看得清文字和焦点。

## 照片按什么归档

首轮沿用「城市相册 → 年份影集 → 照片」。「城市地图」与「我的相册」打开同一份资料。相册与年份由本人选择，原图即使缺少定位和拍摄日期也可以归档。

| 用户的情况 | 本轮规则 |
| --- | --- |
| 春天和秋天各去一次杭州 | 两次都选「杭州 · 2026」时，照片进入同一本年份影集。新加入的照片排在末尾，原有手动顺序保留。 |
| 同一趟行程先去杭州，再去苏州 | 两地照片分别放入本人选定的城市和年份。从地图、相册进入，都能找到同一批照片。 |
| 想先建影集，或记不清年份 | 可先建空影集。年份未知时可选「未标年份」，排在具体年份之后。同城重复创建同一年份会打开已有影集。 |

按一次旅程浏览也有价值，尤其适合同年多次去同一城市或跨城市出游的人。本轮优先解决打开应用和找相册的体验，已有资料可以原样使用。以后若常常想按“那一次旅行”找照片，再评估可命名、可跨城市的旅行相册。

## 怎样验收前端

以下均为**待执行**场景。使用 Edge 和两类隔离测试账号。AC-04、AC-07 各用一个刚注册的空账号独立执行。已有资料的账号在一座城市有两个年份的合成照片，在另一座城市只有空影集。用禁用浏览器缓存的新页面验证首次访问，地图故障测试只阻断地图专用请求，保持账号和相册服务正常。

| 编号 | 实际操作 | 通过条件 |
| --- | --- | --- |
| AC-01 首页好辨认 | 分别以桌面（1280 × 800）和窄屏（375 × 812）打开首页。请一位未看过原型的人从首页分别完成“看哪些城市留有照片”“找一本旧相册”“存入刚拍的照片”。 | 两张浏览卡和添加按钮均在首屏。三次任务首次点选分别命中「城市地图」「我的相册」「添加照片」。窄屏无横向滚动，三个入口均有可见的键盘焦点，按 Enter 可进入。 |
| AC-02 相册和添加照片不等地图 | 在已登录状态下禁用缓存，分别从首页进入「我的相册」和「添加照片」。另开新页面直接访问相册。记录每条路径的请求。 | 相册可浏览或显示新账号空态，添加入口可选城并进入导入流程。三条路径的全国几何数据与地图专用城市接口均为 0 次请求。现版对应请求为 `/map-data/china-cities.v1.json` 与 `/api/v1/map/cities`。 |
| AC-03 地图按需加载 | 从首页点地图，延迟响应，在等待时返回首页进相册。再阻断地图请求，重新进地图，看到失败提示后解除阻断并点重试。 | 进入地图才发起地图请求。等待中可离开，失败后能重试或去相册。重试成功可选城，有有效照片的城市点亮，只有空影集的城市保持未点亮。 |
| AC-04 先建空影集，再添加照片 | 阻断地图请求，用新账号从「我的相册」空态选城并创建空影集。返回首页点「添加照片」，选同一城市，给一张无定位信息的合成照片指定该年份并确认保存。打开旧选城书签 `/#choose-city-title`。最后解除阻断，进入地图。 | 空态和旧书签都能选城。地图不可用期间，空影集可以创建，首页添加的原图可在刚建的影集中打开。恢复地图后，该城市点亮。 |
| AC-05 回到刚才的位置 | 在「我的相册」筛年份，打开某城某年并查看原图，再逐级返回。另从放大后的地图进同一城市并查看同一张照片，再返回。直接刷新已有城市或年份影集地址。 | 两条路径看到同一照片及文字。逐级返回时相册保留本次筛选和浏览位置，地图保留本次视角。已登录用户刷新原有城市、影集地址仍打开对应内容。 |
| AC-06 旧资料和账号隔离 | 用重构前已建的合成资料，分别从两个浏览入口查看原图、顺序和文字。以另一账号登录，尝试打开前一账号的影集和原图链接。 | 原账号已有照片可直接浏览，数量、归属、顺序和文字与原记录一致。另一账号只看到自己的相册及点亮状态，也无法读取前一账号的私人链接。 |
| AC-07 直接保存第一张照片 | 从零影集、零照片的账号开始。在首页点「添加照片」，选杭州和一张无年份编号、无定位信息的合成照片，手动指定 2026 年。确认队列、上传并校验，查看待保存状态，再确认保存。 | 全程无需先去「我的相册」建影集。校验完成时照片显示待保存。确认保存后刷新，从「我的相册 → 杭州 → 2026」能找到唯一一本该年份影集，其中恰有一张照片，点开可看原图。 |
| AC-08 首页入口可操作耗时 | 按下方方法先测现版，再测新版。对比两个版本的「我的相册」入口，另测新版「城市地图」和「添加照片」。 | 验收记录列出各入口的原始耗时、中位数及「我的相册」的新旧差值。新版三个入口各自的中位数均不超过开发前记录的耗时上限。 |

**AC-08 计时方法**

1. 在同一台电脑、同一 Edge 版本和网络条件下，使用前端构建版和相同的合成账号资料。保留登录态，服务已就绪，每次以新页面打开首页并禁用浏览器缓存。
2. 从浏览器开始导航到首页计时。用自动化在目标入口首次可点击时立即点击，以发出点击的时刻结束计时，并验证实际进入对应页面。现版测顶栏「我的相册」，新版测首页主内容的两张卡和添加按钮。每个入口独立冷启动测 5 次，取中位数，单位为毫秒。
3. 实现新版前，先测现版首页「我的相册」，据实测结果在验收记录中写明新版三个入口的耗时上限及理由。新版按同样方法复测。「我的相册」用于新旧对照，其余两项按新版目标判定。目前基线与上限均待实测确定。

验收记录还应附两种尺寸的首页截图、AC-02 三条路径的冷启动网络记录和各场景的结果。视觉效果由原型评审核对。

## 贯穿重构的产品约定

- **原图与导入**　从电脑或 U 盘选择照片，确认保存后可移走源文件并重新打开原图。保存的字节与源图一致。文件名编号只辅助核对，重复照片由本人决定保留哪份。失败的导入须显示失败，保留重试途径。
- **整理与恢复**　照片移动后保留原图和单张文字。手动排序可在重启后恢复。回收站保留 30 天，恢复后照片回到原影集。备份与恢复须能还原照片归属、原图、顺序与文字。
- **使用环境**　优先验收电脑端 Edge，窄屏核对首页的浏览与操作。首轮使用现有本机服务。公开部署和跨电脑访问继续按 T17 单独验收。

当前版本的操作和异常处理见[功能使用指南](../current/guides/user-guide.md)，接口与数据规则见[数据与接口设计](../current/architecture/data-api-design.md)，交付状态见[开发计划](../current/planning/development-plan.md)。

## 设计参考与历史依据

- Apple 照片允许用户主动打开地图按地点浏览，也提供按一次旅程回看的入口。这两种查找方式帮助区分了“去过哪里”和“哪次出游”。[按位置浏览照片](https://support.apple.com/zh-cn/guide/iphone/iph390138909/ios) · [查找旅程照片](https://support.apple.com/zh-hans/guide/iphone/iph7cce5d7a2/ios)
- Google 相册支持为相册命名和指定封面。此间集借用以名称和封面辨认相册的做法，首轮使用已有城市名和封面。[创建和编辑相册](https://support.google.com/photos/answer/6128849?co=GENIE.Platform%3DDesktop&hl=zh-Hans)
- 第一版 R-21 曾要求“地图是首页主体”。本轮由三个功能入口取代该条。旧版规则和任务编号仍可追溯。[第一版需求与验收原文](https://github.com/Staid-hhq/city-memories/blob/c435dacba522a426b7d6eefbc0e38e063ce90720/docs/product/requirements.md)
