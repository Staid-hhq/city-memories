# T03 城市和年份影集交付记录

日期：2026-09-22。状态：已完成。本次实现城市搜索、本人城市手帐、年份影集创建与读取，沿用暖色旅行手帐页面；不实现地图、上传、照片浏览或删除。

## 实际数据流

登录后先读取可选城市和自己的城市统计。选城后只读取当前账号的年份影集；选择 1–9999 的整数年份或“未标年份”后提交。服务端从会话取 owner_id，通过数据库唯一索引原子地创建或返回旧影集：新建 201/created=true，已有 200/created=false，ID、内容、revision 和创建时间均不覆盖。响应丢失可按相同年份重试。

年份从大到小、未标年份最后。空影集写入 SQLite 并保留，城市统计包含空影集，但点亮和照片数只计算本账号的有效照片。页面的“添加照片”明确显示未开放，不触碰源照片。T04 才接入真实原图保存。

## 接口与安全边界

- 实现 `GET /cities`、`GET /me/atlas`、`GET/POST /cities/{city_id}/albums`、`GET /albums/{album_id}`；五类操作都要求登录。响应字段与分页格式见 [接口设计](data-api-design.md)。
- city_id 是公共目录的稳定业务 UUID，album_id 必须属于当前会话账号；他人影集和不存在影集均返回 404。请求不能指定 owner_id；未知字段和非整数年份（包括布尔值、数字字符串、浮点数）返回 422。
- 创建沿用 T02 的来源、CSRF 和 no-store 边界，JSON 请求体最多 16 KiB。并发冲突由两个部分唯一索引处理，第一次写入后才查询，不以“先查再插”依赖应用锁。
- 城市和年份列表默认 24、最多 100 条，使用稳定字段加 ID 的签名游标；游标绑定查询范围，私人年份游标还绑定账号、城市，不能跨账号或换查询复用。新增到已读页之前的年份需刷新后查看。
- 页面退出/换号时整体卸载私人视图并取消请求，旧会话响应不能填回新账号。网络失败与无结果分开提示；保存失败保留已填年份，分页失败保留已读卡片。
- 三城映射范围、证据、在线核验限制及稳定 ID 见 [城市映射记录](t03-city-mappings.md)。真实 Key 不参与运行，也不进 Git。

## 运行和复验

本机项目库已从 `4a097ff7fccb` 升级到 `b61e24f803a7`。其他已有 T02 工程先停止旧后端，在 `backend/` 执行 `uv run python -m alembic upgrade head`，然后按 [README](../README.md) 启动。迁移只增加三项公共城市资料，不读取或修改私人照片。本机 `alembic.exe` 启动器被 Windows 应用控制阻止，改用同一项目 `.venv/Scripts/python.exe -m alembic` 成功执行，没有更改安全设置。

后端：`uv run ruff check .`、`uv run pytest -q`。前端：`npm run lint`、`npm run build`、`npm run test:e2e`。Edge 回归要求 8000/5173 空闲，不复用正在运行的用户服务。uv 缓存受限时可用项目 `.venv/Scripts/` 下工具，依赖锁文件保持不变。
