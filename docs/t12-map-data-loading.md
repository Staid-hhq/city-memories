## 5. 加载和故障方案

### 原型瓶颈

`load() → 全国目录`；`outline() → 同队列依次请求 34 省`；`boundary() → 仍在同一队列`。虽然调用方用了 Promise.all，限速器保证任一时刻只有一个行政请求，开始间隔至少 1500 ms。

按网络响应瞬时返回的最佳条件，从目录开始到最后一省开始有 34 个间隔，最低为 **51 秒**；只计算 34 省自身的相邻间隔则为 **49.5 秒**。实际还包含响应、解析和绘制；某请求超过间隔会进一步拉长。这是代码推导及合成时钟结果，不是本次真实网络测时。排在省面后面的城市边界也会等待，不宜只调 Promise.all 并发或突破限流。

### 推荐的 T13 顺序

1. 页面框架、本系统已核验城市搜索、已有影集和本人统计独立加载，不等待地图引擎、全国目录或轮廓。
2. 官方 HTTPS WMTS 底图/注记启动，与单次全国候选目录请求并行；目录 childLevel=2、extensions=false 已实测可用。不再自动调用原型 outline()，不依赖当前异常的天地图 JS SDK；底图与 SVG 共用同一 Web Mercator 视图及投影，不混搭经纬度瓦片。
3. 目录和业务映射按代码 join：未审核候选不直接创建正式影集；已核验城市即使地图失败也可搜索进入。全国列表发布前完成第 3 节审核。
4. 对本人有效照片城市按需取边界，优先当前选中城市、其次可见有照片城市。无照片不取；视野外延后，不全国遍历。全国总览里大量有照片城市先显示已核验入口点，区域逐步补齐，明确“区域加载中”，不暗称全部区域已就绪。
5. 行政接口保留单路/至少 1500 ms 起步间隔作为当前保守设置，不宣称这是官方 QPS 配额。计划最多保留 20 个待发边界任务，离开视野清除尚未开始任务；已在途请求结果可留页内公共几何缓存。点击结果/统计用账号和视图代次保护，退出换号立即去掉私人点亮。
6. 请求去重和公共几何只在页内内存复用；不写磁盘、localStorage、IndexedDB、Service Worker 缓存或仓库，不为提高速度批量下载轮廓。浏览器正常 HTTP 缓存行为另计，不主动做离线数据副本。
7. 配置无效、401/403、配额/302010、超时、损坏几何分别给出脱敏提示；不自动无限重试。单次行政请求沿用 25 秒上限，交互在 8 秒仍未完成时即展示可用文字入口和重试状态（请求可以仍在途）。手动重试只补失败项，错误日志不得包含 tk、完整请求 URL 或私有统计。
8. 返回地图保留中心/缩放；未取完区域不阻止影集入口。城市业务变更成功后重读本人统计；归属、删除/恢复只由本系统决定，不向地图供应商提交照片、文字、账号标识或上传目录。

这减少首次进入的行政请求数，但瓦片请求仍占所用服务额度；若以后再引入 SDK，还需计入 SDK 消耗。不能承诺同样外观或正式产品速度已实现；暖色和浅省界效果需要 T13 实际呈现给用户审阅。
