## 来源和对照方法

- 内地和港澳名称、层级与代码：民政部 [全国行政区划信息查询平台](https://dmfw.mca.gov.cn/XzqhVersionPublish.html) 的公开当前树接口 [xzqh/getList](https://dmfw.mca.gov.cn/xzqh/getList?code=0&trimCode=true&maxLevel=3)。本次读取的是 **2026-10-04 的当前树**，不能因页面版本表默认选项而把它标为“2025 年固定目录”。保留地级市、自治州、地区、盟及省直辖县级单位；四个直辖市各一入口，港澳各一入口；普通地级市下辖区县不独立建入口。
- 台湾地区：按用户在 T12 确认的天地图市/县目录口径保留 20 项，以 [中国政府网台湾省行政区划说明](https://big5.www.gov.cn/gate/big5/www.gov.cn/guoqing/2020-07/28/content_5530577.htm) 交叉核对名称。此来源用于名称核对，不宣称它是 2026 年最新编码表；页面列举的金门、连江不在天地图台湾节点中，不据此自行改变供应商树或新增重叠入口。台湾 `provider_code` 是供应商映射，不能称为全国统一行政代码。
- 坐标和区域：仍仅使用天地图 [行政区划 V2](http://lbs.tianditu.gov.cn/server/administrative2.html)。前端每次页面生命周期读取一次全国目录，按业务 UUID 关联的 **供应商代码 + 名称 + 上级名称 + 类型对应层级** 匹配，拒绝重复编码、跨省归属错误和无效坐标；不以重名、单一返回项或名称后缀代替审核。真实正式页面实测中，391 项全部准确对应，无遗漏；响应只在内存核对，不保存原始全国目录。

## 稳定归属与门禁

1. 正式业务标识使用独立 UUID v4。T03 的深圳、广州、贺州三个 UUID 原样保留；新增城市只生成一次，供应商换码不能更换照片/影集的归属 ID。
2. 每次启动在单实例锁内补充缺失记录，使用冲突忽略；不重写已有名称、映射状态或停用状态，不重新启用人工暂停的城市。没有新增迁移，迁移头仍是 `b61e24f803a7`。
3. `/cities` 和 `/map/cities` 仅开放有效且 `verified` 的记录；新建影集继续由后端门禁检查。地图供应商响应不能自动在数据库注册入口。已有停用城市影集仍依 T03 规则由本人查看，不丢失关联。
4. 边界仅按精确代码查询，并检查返回代码、名称和合法 WKT；保留多面、离岛和洞，不把坐标系不同、空边界或错码响应画成“已成功”。一个城市失败不阻断城市文字入口。
5. 后续改名/换码应先记录新旧来源、日期、名称/父级/类型差异，人工核对后更新同一个业务 UUID。拆分/合并及既有影集如何归属需单独决策，不在启动同步中自动迁移私人资料。

本仓库公开的只有最低限度的业务身份事实与审核出处，不是供应商响应镜像，不打包全国几何；真实响应、截图、运行资料与 Key 均留在忽略目录。公开部署时的服务条款、域名限制、图层审图信息适用性及实际用量仍在 T17 复核。本次映射完成不表示应用已获地图审查或已公开上线。

### 核对依据和边界

- 平台编码复用现有 [原型映射](../../prototype/travel-journal/app.js) 中的明确对应关系；目录来源、深圳具体响应和 2026-09-21 的在线读取记录见 [数据来源说明](../../prototype/travel-journal/assets/china-cities-source.md)。没有通过拼接省级编码伪造城市入口，也没有复制整个供应商目录。
- 名称与六位行政区划代码交叉核对 [中国政府网公布的行政区划代码表](https://www.gov.cn/gzdt/att/att/site1/20091113/00123f3eabca0c6759ac01.pdf)、[深圳市政府的代码说明](https://www.sz.gov.cn/ztfw/shbz/wyw_184041/ywzsk_184570/content/post_8533553.html) 和 [广东政务服务网广州入口](https://www.gdzwfw.gov.cn/portal/index?region=440100)。政府代码表是历史发布的事实核对资料，不声称是 2026 年全量最新目录，也不替换天地图供应商映射。
- 本轮尝试带既有 Key 的单城在线核验，被执行环境的安全审查阻止，命令未执行；没有读取或外发该 Key。以上映射使用已保存的原型证据与公开资料，未宣称完成新一轮天地图在线响应核验。
- `verified` 在 T03 仅表示这三项名称、归属和既有平台代码已人工交叉核对，可以创建业务影集；不表示行政几何、全国覆盖、官方底图呈现或供应商条款已验收。特殊行政单位仍留在 T12 逐项核对。

### 入库与长期归属

迁移 `b61e24f803a7` 只插入这三项公共业务资料，不生成账号、私人影集或照片。重复执行 `alembic upgrade head` 不重复插入，也不覆盖运营中已停用的城市。业务 ID 与平台编码分离，后续平台改码不更换影集的 city_id。

仅 `is_active=1` 且 `mapping_status=verified` 的城市出现在可选目录并允许新建影集。停用或回到待核对状态后，已有影集仍能由其主人通过“我的城市手帐”查看；其他账号看不到该历史。降级迁移不连带删除影集，存在引用时由外键拒绝删除映射。
